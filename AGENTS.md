# Agent Guidelines: skillcn

This document provides instructions and standards for agentic coding agents operating in the `skillcn` repository.

## 🛠 Development Commands

| Task           | Command                | Description                                      |
| :------------- | :--------------------- | :----------------------------------------------- |
| **Build**      | `pnpm run build`       | Builds the project using `tsdown`.               |
| **Lint**       | `pnpm run lint`        | Fixes linting and formatting issues using Biome. |
| **Check Lint** | `pnpm run check-lint`  | Verifies linting without modifying files.        |
| **Type Check** | `pnpm run check-types` | Runs `tsc --noEmit` to verify TypeScript types.  |
| **Format**     | `pnpm run format`      | Runs Biome formatter only.                       |
| **Test**       | N/A                    | No tests are currently implemented.              |

## 🎨 Code Style & Conventions

### 1. General Standards

- **Runtime:** Node.js (>=20.0.0).
- **Module System:** ESM (`"type": "module"` in `package.json`).
- **Formatter/Linter:** [Biome](https://biomejs.dev/). Do not use Prettier or ESLint.
- **Indentation:** 2 spaces.
- **Quotes:** Double quotes.

### 2. TypeScript Guidelines

- **Strict Mode:** Enabled. Always provide explicit types for function parameters and return values.
- **Naming:**
  - Functions/Variables: `camelCase`
  - Classes/Interfaces/Types: `PascalCase`
  - Constants: `UPPER_SNAKE_CASE`
- **Imports:**
  - Use the `node:` prefix for built-in modules (e.g., `import { join } from "node:path"`).
  - Biome automatically organizes and sorts imports.

### 3. Error Handling

- Use `try/catch` blocks for asynchronous operations.
- Provide descriptive error messages using `picocolors` for CLI output.
- In CLI commands, use `process.exit(1)` on fatal errors to signal failure to the shell.

### 4. CLI & UX Patterns

- **Colors:** Use `picocolors` for consistent status indicators:
  - `green("✓")` for success.
  - `red("✗")` for failures.
  - `yellow("⊘")` or `yellow("⚠")` for warnings/skips.
  - `cyan()` for variable names or highlights.
- **Interactions:** Use `@clack/prompts` for user input, confirmations, and spinners.
- **Logging:** Use `bold()` for headings and maintain clean spacing in CLI output.

## 📂 Project Structure

- `src/index.ts`: CLI entry point. It handles banner printing, command registration using `commander`, and global error catching.
- `src/commands/`: Implementation of CLI commands.
  - `add.ts`: Logic for installing skills into the user's project (`.agents/skills/`). Handles dry runs and file system operations.
  - `list.ts`: Logic for listing available skills in the `skillcn` library.
  - `index.ts`: Export hub for all commands.
- `src/skills/`: Source directory for reusable agent skills.
  - Each skill is a directory containing a `SKILL.md` file that describes its purpose and provides instructions.
  - New skills should be added here and mirrored in the `dist/` folder after building.
- `dist/`: Compiled output generated by `tsdown`. Do not edit files here directly.
- `biome.json`: Configuration for linting, formatting, and import organization.
- `tsdown.config.ts`: Build configuration for the project.

## 📋 Best Practices for Contributors

### 1. Adding a New Command

1. Create a new file in `src/commands/`.
2. Implement the command logic as an exported asynchronous function.
3. Import and export the new function in `src/commands/index.ts`.
4. Register the command in `src/index.ts` using `program.command()`.
5. Ensure the command follows the established CLI UX patterns (using `picocolors` and `@clack/prompts`).

### 2. Adding a New Skill

1. Create a directory under `src/skills/` with a descriptive name (kebab-case).
2. Create a `SKILL.md` inside that directory.
3. Follow the structure of existing skills:
   - Provide a clear name and description.
   - List available tools or specific instructions.
   - Use Markdown headers for organization.

### 3. File System Operations

- Always use `node:fs/promises` for asynchronous file operations.
- Use `resolve()` and `join()` from `node:path` to handle cross-platform path compatibility.
- When working with local paths in ESM, use `fileURLToPath(import.meta.url)` to derive `__dirname`.

## 🤖 AI Context

When creating new skills in `src/skills/`, ensure they follow the `SKILL.md` format seen in existing skills. When modifying the CLI, maintain the existing pattern of separating command logic into the `src/commands/` directory. Agents should proactively run `pnpm run check-lint` and `pnpm run check-types` before submitting changes to ensure code quality.
